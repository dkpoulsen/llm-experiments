# Tag: memory-budget

- [[published-as-a-conference-paper-at-iclr-2022]] — 8-Bit Optimizers via Block-Wise Quantization (ICLR 2022) — Dettmers, Lewis, Shleifer and Zettlemoyer (Facebook AI / UW, ICLR 2022, arXiv 2110.02861) - first 8-bit optimizer states that match 32-bit performance, via block-wise dynamic quantization (independent 2,048-element blocks with non-linear mapping, so outliers do not consume the quantization range) plus a stable embedding layer to damp gradient variance from skewed token distributions. States that optimizer state is 33-75% of total training memory and that Adam and Momentum use 8 and 4 bytes per parameter - 8 GB and 4 GB for a 1B model - cut to 2 GB and 1 GB at 8 bits, a 4x reduction on the state term. Validated on 1.5B and 355M language-model pretraining, GLUE, ImageNet, WMT14, MoCo v2 and RoBERTa with no hyperparameter changes; drop-in two-line code change. For this run it is the load-bearing counter-example to the repo's memory arithmetic: 8-bit Adam would take a 7B fully-trainable model's optimizer state from 84 GB (fp32 m + v + master) to roughly 14 GB, which changes the DDP-fits-on-64-GB verdict without freezing any Engram tables. `review`
- [[adafactor-adaptive-learning-rates-with-sublinear-memory-cost]] — Adafactor: Adaptive Learning Rates with Sublinear Memory Cost — Shazeer and Stern (Google, arXiv 1804.04235, 2018) - Adafactor replaces Adam's full per-parameter second-moment matrix with a factored approximation: keep only the per-row and per-column sums of the moving average of squared gradients and reconstruct the per-parameter estimate from them, which is exact for rank-1 matrices and requires space proportional to n + m rather than nm. Adds update clipping and a gradually increasing decay rate to stop adaptive methods producing oversized updates, and scales updates relative to parameter scale; drops momentum. Matches the published Adam regime on WMT14 English-German Transformer training while using very little auxiliary optimizer storage. Frames the baseline as Adam's two auxiliary parameters per model parameter tripling memory requirements. For this run: Adafactor state is at most ~4 bytes per parameter (versus 8 for Adam m + v) and far less for large matrices, so it is the cheapest way to keep a 7B model fully trainable inside 64 GB without sharding - though it changes the optimizer and therefore the comparability of any run against the repo's Adam-based baseline. `review`
- [[memory-efficient-llm-training]] — Memory Efficient LLM Training — Archie Sengupta blog, Memory Efficient LLM Training (~5,100 words) - practitioner survey of the training-memory stack, useful mainly as an arithmetic reference. Per-parameter accounting: fp32 weights 4P, fp32 grads 4P, Adam first plus second moment 8P, bf16 copy 2P; activations grow quadratically with sequence length and linearly with batch. Gradient checkpointing: full checkpointing costs ~30-40% compute overhead, every-K checkpointing gives ~Kx memory for 20-30% overhead. Gradient accumulation: memory stays at micro-batch size while AllReduce frequency falls with accumulation. ZeRO stages: per-GPU memory 2P + 8P/N (stage 1 and 2) and 12P/N (stage 3), with stage 3 costing O(N) AllGathers per layer per forward/backward pass, which is why ZeRO-3 is normally paired with tensor parallelism inside a node. ZeRO-Offload and FSDP CPU offload cost 10-20% to 30-50% slowdown. Its topology table assumes NVLink at 900 GB/s for TP and PP and InfiniBand at 50 GB/s for DP - there is no PCIe-Gen2-only case anywhere in the piece, and its only fabric-relevant statement is that TP must stay within a node (NVLink required). Internal inconsistency worth flagging: it states Adam needs 8 bytes per parameter but its total equation is P x (4+4+4+2) = 14 bytes, i.e. only 4 bytes of optimizer state; the repo's 112 GB / 7B figure uses the correct 12 bytes (fp32 m + fp32 v + fp32 master). `review`
- [[published-as-a-conference-paper-at-iclr-2018]] — Mixed Precision Training (ICLR 2018) — Micikevicius et al. (NVIDIA with Baidu, ICLR 2018, arXiv 1710.03740) - the standard mixed-precision training recipe: store weights, activations and gradients in IEEE fp16, keep an fp32 master copy of the weights that accumulates the optimizer updates and is rounded to fp16 for forward and backward, use loss scaling to stop small-magnitude gradients flushing to zero, and accumulate fp16 products into fp32 outputs. Nearly halves memory versus fp32 and exploits 2x-8x higher half-precision arithmetic throughput on tensor-core GPUs, with no changes to models or hyperparameters, validated across image classification, generation, detection, language modeling, translation and speech. This is the source of the +2 bytes/parameter master-copy term in every memory budget in this run: bf16 weights (2) + bf16 grads (2) + fp32 master (4) + Adam m and v (8) = 16 bytes per parameter for a fully trainable model, which is what makes 7B fully trainable cost ~112 GB. `review`
