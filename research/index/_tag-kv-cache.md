- [[deepseek-v41-flash]] — DeepSeek-V4.1-Flash: — DeepSeek-V4.1-Flash technical report (DeepSeek-AI, arXiv 2609.19969v1, 17 Sep 2026): a 552B-backbone multimodal MoE with a Causal Encoder-Decoder (CED) split of 20 encoder + 20 decoder layers, activating 8B params/token in prefill and 16B in decode, pretrained on 45T tokens at a fixed 100.6M-token batch. CSA2 is the paper's central KV-compression mechanism and differs materially from the repo's description of it: it is NOT a per-layer indexer running in parallel everywhere. Each CSA2 layer is statically assigned one of three modes — Full (own main KV, own indexer Q, fresh Top-K), Reindex (borrows a preceding layer's main KV + indexer K, rescores with its own indexer Q), Reuse (borrows both KV and the latest Top-K indices, no indexer at all). In the actual 40-layer configuration only 4 layers run a Full-mode indexer (3 encoder + 1 decoder), 4 run Reindex indexers, 27 are Reuse (zero indexer work), and the first 2 layers are pure SWA — 67.5% of layers execute no indexer at all. Hyperparameters: attention top-k = 512 KV entries per query; indexer 32 query heads, head dim 128; main attention 64 heads, head dim 512, query compression dim 1280; SWA window 128; compression ratio m=2 in encoder layers and m=1 in decoder layers; Hierarchical Sparse Indexer selects at most 2,048 blocks of 8 positions = 16,384 candidate positions. The hierarchical indexer is "used only in the decoder of CED to reduce this repeated scoring during decode" and is "introduced in post-training", with the candidate restriction applied identically during training and inference so deeper indexers are optimized under the same search domain they use at inference; the first Full-mode layer still scans the entire causally visible range. Result: 890 bytes/token global KV cache (~1/4 of V4-Flash) and nearly flat decode FLOPs (256-fold context growth 4K→1M raises decode FLOPs only 1/4).

Training-side facts that bear directly on the repo's CSA2-at-32k claim: (1) sparse attention is trained FROM SCRATCH at sequence length 64K with NO dense-attention warm-up stage, then extended to 1M at 34T tokens — so 32k is below the paper's trained regime, not a natural operating point; (2) FP4 global KV caches are used DURING TRAINING with only marginal performance degradation (QAT extended from the FP4 indexer Q/K to the main KV cache, MXFP4/NVFP4-style block scaling); (3) distributed CSA2 training needs extra machinery the repo does not budget for — "shadow indexers" (a lightweight executable replica per pipeline stage with a single logical owner, kept consistent by parameter sync and gradient aggregation), pipeline payload extensions carrying intermediate representations and sparse routing information across stage boundaries, and micro-batch-level shared-state management coordinating state lifetimes across forward, activation recomputation and backward; (4) Engram tables are partitioned by row across engram-parallel process groups, optimizer state is sharded across replicas, embeddings are stored/fetched in FP8, prefetch is initiated for the whole local batch before each pipeline stage, and embedding gradients are buffered during backward and returned to owning ranks after the backbone backward — Engram LR is scaled 5x. Optimizer mix: Muon for linear transforms, AdamW for RMSNorm/non-matrix params, Sinkhorn-balanced update for embeddings and prediction head. Reuse-mode layers execute with only 15 kernels during prefill and 11 during decode. 24,845 words — long source, flag for source-analyst. `review`
- [[kv-kaizen-learning-context-adaptive]] — KV-Kaizen: Learning Context-Adaptive — KV-Kaizen (Monteiro, Bethune, Filippova, Laguna, Grangier, Cuturi — Apple, arXiv 2609.37988) learns a context-adaptive per-layer KV cache configuration along three axes — depth (sharing one cache across layers, i.e. inheriting an earlier layer's cache), precision (fewer bits, {2,4,8,16}), and rank (truncating the MLA latent representation) — under a single bits-per-token budget. A small selector reads the prompt once before prefill and picks one of 17 actions per layer; the configuration then holds for every generated token, and selector and model are trained together during supervised fine-tuning so the model adapts to the cache it will be served under. The budget can itself be an input, so one selector serves several compression targets.

Findings: applying any single axis uniformly across all layers limits achievable compression because it degrades accuracy, whereas composing mild settings locally and adaptively preserves accuracy at much higher compression. A 4x cache reduction incurs no accuracy degradation from 7B parameters up; on Qwen2.5-14B at 16k, 4x cache compression composed with eviction to one position in eight yields a 32x smaller decode-time cache while preserving accuracy (the two ratios multiply). Compressed models are more accurate than smaller uncompressed models with the same cache size, and selectors reach the Pareto frontier of accuracy vs cache size against learning-free and post-hoc baselines. Theoretical maximal compression for a 48-layer model such as Qwen2.5-14B is 4108x (8x precision x 10.7 lowest rank x 48 depth), though all experiments target far lower factors.

Relevance to the CSA2 question: this is the inference-side counterpoint — substantial KV compression (4x with no loss from 7B up, 32x composed with eviction) is achievable post hoc, without architectural sparse attention and without from-scratch sparse pretraining. The paper's own framing is "these findings support pre-training large models and compressing them only afterwards." 16,061 words. `review`
