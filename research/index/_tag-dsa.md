- [[deepseek-v32-pushing-the-frontier-of-open]] — DeepSeek-V3.2: Pushing the Frontier of Open — DeepSeek-V3.2 technical report (arXiv 2512.02556) — the origin of DeepSeek Sparse Attention (DSA) and therefore the primary source for the indexer training recipe the repo infers. The lightning indexer computes an index score between each query token and the latent KV entries using a small number of indexer heads and a ReLU activation (chosen for throughput rather than softmax), and a fine-grained token-selection mechanism retrieves only the top-k KV entries, reducing core attention from O(L^2) to O(Lk) while the indexer itself retains a complexity that grows with sequence length.

The two-stage training recipe is stated with exact numbers. Dense warm-up: keep dense attention and freeze all model parameters except the lightning indexer; build a target distribution by summing the main attention scores across all heads and L1-normalizing along the sequence dimension; minimize a KL divergence between that target and the softmax of the indexer scores; LR 1e-3; 1000 steps of 16 sequences of 128K tokens = 2.1B tokens. Sparse training: introduce fine-grained token selection and optimize all parameters; keep the KL alignment but renormalized over only the selected token set S_t; detach the indexer input from the computational graph so the indexer's training signal comes only from its own KL loss while the main model is optimized only on the language-modeling loss; LR 7.3e-6; select 2048 KV tokens per query; 15000 steps of 480 sequences of 128K tokens = 943.7B tokens.

Two facts matter most for the repo's CSA2-at-32k claim: (1) the DSA lineage trains at 128K sequence length, not 32k — both the 2.1B-token indexer warm-up and the 943.7B-token sparse stage use 128K sequences; (2) the indexer and backbone are trained as two separate objectives via a detached graph, which is the concrete mechanism behind the repo's "extra loss term, not a drop-in" claim. The report also covers the 128K long-context extension and the post-training recipe (specialist distillation plus mixed RL). 9,409 words. `review`

The indexer backward is the decisive confirmation of the run's 'separate distillation loss' claim: it forms a clipped-log KL gradient from the supplied FP32 index_score exactly as the kernel's _score_grad_inplace stage does — eps = exp(-100.0) (kernel CLIP_LOG_MIN), g = -max(target,eps)*[predict>=eps], grad_signal = g - predict*sum(g), masked where topk_indices<0 — and backpropagates through scores recomputed from (index_q, weights, index_k, topk_indices).
